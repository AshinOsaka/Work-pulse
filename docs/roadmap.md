## Extension points already in place

* **Agent events:** the agent API accepts a closed set of event types. New capabilities (Phase 5 added
  `activity.segment`; tray task selection is planned) are added as new, explicitly reviewed event types, never free-form payloads.
* **Auto-update:** the release endpoint and the update flow are designed in `docs/agent-packaging.md`.
* **Scope:** `AccessScopeService` already decides which employees a viewer may see. Activity (Phase 5) and screenshots
  (Phase 6) and live viewing (Phase 7) use it, so a manager only sees monitoring data for their own reporting line.
* **Authorization:** the permissions each future module needs (`SCREENSHOT_VIEW`, `LIVE_STREAM_VIEW` and
  others) already exist and gate navigation.
* **Dashboard data:** every dashboard widget reads from the `DashboardDataSource` interface. Phases 4, 5 and 8
  replace empty methods in `live-source.ts` with real API calls, and the widgets don't change.
* **Realtime:** an authenticated gateway, a connection registry and an event envelope, with reserved
  namespaces for presence, activity, alerts and WebRTC signalling.
* **Audit:** `AuditService` records sign-ins, password changes, registrations and all organisation changes
  (employees, status, invitations, roles, departments, teams, devices).
* **Custom roles:** the `roles` collection supports company-specific roles (with `company_id` set); the UI and
  assignment flow are planned.
* **E-mail:** an `EmailSender` protocol. Add an SMTP or SES implementation and select it with `EMAIL_BACKEND`.
